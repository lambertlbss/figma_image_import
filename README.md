# Figma Image Folder Importer

把本地 PNG 资源目录导入 Figma，并在后续选择同一资源目录时执行增量同步。

每次功能更新和问题修复记录在 [CHANGELOG.md](CHANGELOG.md)。

## 功能

- 只根据资源根目录下的第一级文件夹创建和识别 Section；更深层目录仍保留在资源相对路径中，不会额外创建 Section。
- 图片以原始尺寸创建为 Component，名称为不含扩展名的文件名。
- 支持两种组件集分类方式：严格尺寸、AI 辅助（Figma MCP，可选）。默认使用严格尺寸；AI 辅助会同时参考严格尺寸、名称模板、路径、尺寸关系和视觉内容，既能拆分同尺寸异类，也能合并跨尺寸同系列资源。
- 使用 SHA-256 对比资源，区分新增、更新、删除、移动和未变化内容。
- 扫描后可点击新增、更新、删除、移动或未变化统计卡片进入独立变动预览页；支持按类型、文件夹和资源路径筛选，并显示更新前后尺寸及移动前后路径。“组件集”页签按同步后的 Component Set 展示受影响分组，标题默认收起，展开后才加载内部本地 PNG 缩略图；“异常资源”页签检查全部有效本地 PNG，显示文件体积、尺寸、单位像素体积、同尺寸中位数以及可疑元数据区块。除“组件集”外的页签保持纯文字，不加载图片。
- 异常资源检测会识别 `iTXt`、`tEXt`、`zTXt`、`eXIf`、`iCCP` 等 PNG 元数据区块，并结合相同尺寸资源的体积离群程度和单位像素体积降低误报；检测只报告问题，不修改本地文件，也不会阻止或改变同步计划。
- 重复同步先用文件大小、修改时间和图片尺寸快速比对，只为疑似变化的文件重新计算 SHA-256；升级后的首次扫描会建立这份快速索引。
- 同步时并发读取文件，并按图片平均大小自适应组成批次：小图片最多 48 个、中等图片最多 32 个、大图片最多 16 个，同时严格限制单批不超过 12MB。
- 新增和结构变化期间只收集待排版节点，结束时每个 Component Set 和 Section 统一排版一次；同尺寸的纯图片更新不会触发布局变化。
- Section 最终排版会把顶部标题区域和四周边距一起纳入评分，优先选择接近正方形的外框；每排内容水平居中，并避免只剩少量内容的突兀尾行。
- 同一分类组只有 1 个资源时保留普通 Component；达到 2 个时自动组成 Component Set，删除到只剩 1 个时自动拆回普通 Component，并保留 Component ID。
- “快速检查”产生的 Figma 页面索引会直接复用于差异分析，避免连续扫描同一批 Section 和 Component。
- 同一次同步内，SHA-256 完全相同的图片复用同一个 Figma Image，并在完成提示中展示读取、导入和排版耗时。
- 同尺寸替换只更新图片填充，保留 Component ID、位置和 Component Set。
- 纯图片替换不会触发排版；当新增、删除或尺寸变化造成 Section 级结构变化时，当前资源库的全部托管 Section 会作为一个整体重新排列，Section 内未变化的资源不会被重写。
- 多个托管 Section 使用固定 `200` 安全间距组成紧凑的页面级布局。插件先按面积从大到小稳定排序，再使用二维矩形装箱让较小 Section 回填前面能够容纳的空区；整体从左上角开始，比例只做柔性约束，不会为了硬凑正方形制造大面积空白。非插件管理的手工 Section 保持原位，托管布局会自动放在其下方或右侧。
- 组件集可使用语义化名称和 Variant 属性；严格尺寸模式仍使用 `宽x高` 与 `Property 1=资源名`，旧版非法名称会在下一次同步时自动修复。
- 删除本地资源前显示差异并要求确认。
- 首次升级可根据 Section、Component 名称和尺寸接管旧版本导入的内容；Figma 遗留的 `组件集名/资源名` 层级 Component 会按末级资源名识别并复用原节点。
- 当前页面只有一个同名顶层 Section 时会直接复用；其中未被插件识别的手工内容不会删除或重写。直属 Component 和 Component Set 即使缺少旧版插件元数据，也会作为资源参与 Section 排版；其他手工内容会统一校正左上边界，避免单个游离节点把整个托管内容推远并制造大面积前置空白。

## 本地安装

1. 在 Figma 中打开 `Plugins → Development → Import plugin from manifest…`。
2. 选择本项目中的 `manifest.json`。
3. 运行插件并选择 PNG 资源根目录。
4. 查看差异数量并选择需要同步的文件夹；需要核对明细时点击任一统计卡片进入变动预览页，也可以在预览页直接确认同步。

## 组件集分类

- **严格尺寸（默认）**：同一一级目录内完全相同尺寸的资源组成以 `宽x高` 命名的 Component Set。
- **AI 辅助（MCP）**：同时生成严格尺寸候选组、名称模板语义候选组和纯尺寸名称优化候选，再由外部 AI 客户端双向审核：拆分同尺寸异类、合并跨尺寸同系列、改名或保持独立。即使成员完全不需要调整，`404x404` 这类纯尺寸组件集也会被单独提交给 AI 审核命名；可靠语义不足时仍可保留原名。仅改名时插件复用原 Component Set 和内部 Component，不重新导图或更换节点 ID。语义候选会识别状态、方向、品质、字形、编号/帧、倍率和一般命名系列，并携带尺寸关系与变化槽位证据。同一 AI 组件集内，按 `sqrt(width × height)` 计算的最大、最小线性尺寸比例不能超过 `1.7506`；该阈值取自组件库 AJ 的 `common` Section 中现有 Component Set 的最大实际差距，插件会在修改画布前强制校验。未被 AI 提及的资源继续保持严格尺寸结果；插件只接受当前扫描对应、格式合法且置信度不低于 `0.7` 的方案，跨一级目录、重复归组或引用不存在资源的方案也会被拒绝。已有 Component Set 只有在名称完全是 `宽x高` 尺寸占位符时才允许 AI 改名；其他语义名称由插件强制原样保留。

### AI 辅助流程

1. 在分类方式中选择“AI 辅助（基于严格尺寸）”。切换分类方式时插件会自动重新扫描当前 Figma 页面；如果页面内容被手工调整，也可以点击“刷新页面”重新计算差异，不需要再次选择本地目录。
2. 在下方勾选需要 AI 审核的文件夹，再点击“生成 MCP 请求”。插件只会把这些文件夹的资源清单、已有 Figma 节点 ID、已有 Component Set 名称及其改名策略、严格尺寸候选组、跨尺寸语义候选组、纯尺寸名称优化候选和审核规则写入当前页面的 shared plugin data，并复制一段提示词。
3. 把提示词交给已连接该文件的 Figma MCP 客户端。AI 可结合名称、尺寸和已有节点截图做判断，但只写回分类 JSON，不直接移动或合并节点。
4. 回到插件点击“读取 AI 方案”，先查看重新计算后的差异和分类摘要，确认后再开始同步。

Figma MCP 是可选项；未连接时直接使用严格尺寸即可。首次导入且 Figma 中还没有对应节点时，AI 主要依据路径、名称与尺寸判断；已有组件库则还能通过请求中的节点 ID 查看现有视觉内容。

## 同步标识

插件通过 Figma `pluginData` 保存资源库 ID、相对路径、内容 Hash、尺寸和所属文件夹。同一个 Section 内以 Component 名称作为唯一资源身份；路径不同但名称相同的新资源会替换旧 Component，并保留节点 ID。

本地同一 Section 内存在多个同名文件时，只保留 `lastModified` 最新的文件。Figma 中已存在的同名 Component（包括旧版本留下的未标记节点）会在同步成功后归并为一个，即使关闭“同步本地删除操作”也会清理同名副本；其他未匹配的手工内容不受影响。文件内容和路径均未变化时，插件不会写入或移动对应节点；唯一 Hash 能匹配的新旧名称仍会被识别为重命名或文件夹移动。
